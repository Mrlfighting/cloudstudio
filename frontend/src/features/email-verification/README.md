# 邮箱验证前端模块

本模块对接现有邮箱验证码接口，不修改后端认证实现。注册表单要求邮箱；登录后，除个人中心邮箱管理外，私有功能须先完成验证。公共图库、图片预览、分享及本地拼豆转换仍可使用。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `api.ts` | 独立 Cookie/CSRF 传输、预期账号头、请求撤销与同账号单次 CSRF 重试 |
| `store.ts` | 状态查询、验证码申请/确认、并发验证门和账号代次隔离 |
| `policy.ts` | 普通业务请求前置检查与公共/认证请求豁免 |
| `EmailVerificationBridge.vue` | 全局挂载、前台恢复、跨标签页通知和失效后的私有视图清理 |
| `EmailVerificationDialog.vue` | 邮箱输入、投递状态、倒计时、验证码和暂缓验证 |
| `EmailSettingsCard.vue` | 个人中心与编辑资料共用的邮箱管理入口 |

## 接口与状态约定

- 使用 `GET /email/status`、`POST /email/binding/request`、`POST /email/binding/confirm`，相对于现有 `/api/v1` 基址。
- 所有请求携带发起时账号的 `X-Expected-User-ID`，授权仍以服务端 Session 为准。
- 申请的 202 只表示已登记，界面显示“正在发送”；仅服务端返回 `sent` 后显示已发送。
- 验证码为六位字符串，保留前导零，仅存内存。关闭弹窗、退出或换号即清空。
- 轮询仅在弹窗可见、页面前台且仍在投递时进行，间隔三秒；重发/过期时间以服务端为准。
- 邮箱请求 401 不重放；账号不一致 409 清除旧登录视图。同账号 CSRF 刷新后最多重试一次。
- 写入前后的状态版本阻止旧查询覆盖新申请；账号代次与 AbortController 阻止迟到响应串号。
- 换绑完成前旧邮箱继续有效。此处不提供解绑界面。
- 认证弹窗和邮箱弹窗依次显示，共享待继续的操作；暂缓则取消该操作，保留登录状态。
- 跨标签页通知只包含账号、时间和随机标识，并触发服务端复核，不能直接授予权限。

## 集成边界

应用根部挂载 Bridge；现有认证门、路由守卫和共享 HTTP 客户端仅作接线。独立拼豆传输同步接入验证检查，未验证时不读取云端列表、不提示迁移，但本地工作区不受影响。

**这是前端访问策略，不构成后端安全边界。** 后端现有业务接口仍按原登录权限运行，直接调用 API 不受此模块限制。上线时须先部署已完成的邮箱后端、数据库迁移及邮件调度器/专用 worker，并配置邮件服务，否则未验证账号无法完成业务前置验证。

## 验证

在 `frontend` 目录运行 `npm.cmd run build`。无新增依赖的浏览器模拟场景说明见 `tests/email-verification/README.md`。测试通过不代表真实邮箱投递已验证；真实投递需在独立环境人工联调。
