# 全接口审查修复与单服务器加固

本轮基于 `feature/email-verification-ui@72bf429`，按用户选择加固现有单服务器。未操作生产数据库、部署或发送真实邮件，代码须验收后才能提交。现有邮箱强制验证仍为前端策略，本轮不将它变成新的后端业务权限。

## 上线步骤

1. 备份数据库和服务器现有配置。本轮未执行这些生产操作。
2. 构建包含本轮代码与锁文件的镜像，可将 [Dockerfile.security](../backend/deployment/Dockerfile.security) 用于既有 Compose 的 `prod`/`migrate` 构建目标；上下文为仓库根。模板读取完整 workspace 元数据，以 `uv export --offline --frozen` 导出并验证安装哈希，避免旧构建复制单份后端 pyproject 后重新解析依赖。不要仅复制前端产物，或跳过数据库迁移。
3. 先检查重复活跃空间：

   ```sql
   SELECT user_id, space_type, count(*)
   FROM spaces WHERE is_deleted = false
   GROUP BY user_id, space_type HAVING count(*) > 1;
   ```

   若有结果，人工确认保留/合并方案。新迁移会停止，绝不自动删除数据。
4. 使用原有独立迁移进程升级至 `a8d9e0f1b2c3`。生产仍需 `CONFIRM_PRODUCTION_MIGRATION=yes`；API 设置 `CREATE_TABLES_ON_STARTUP=false`。
5. 将 [安全配置占位模板](../backend/deployment/security.env.example) 合并进服务器现有环境；保留原密钥，不轮换、不复制本地真实 `.env`。校对 Redis 地址、密码、CORS 域名、代理链及负载预期限额。
6. 将 [Compose 覆盖模板](../backend/deployment/security.compose.yml) 叠加到服务器已有 Compose。服务名为 `api`，其他命名需对应调整；保留原生产构建、证书和数据库卷配置。
7. 如需通过网关探测，将 [Nginx 就绪检查片段](../backend/deployment/nginx-readiness.conf.example) 合并进既有 HTTPS server；默认仅允许回环地址，需要外部监控时精确添加其可信 IP，不向匿名公网开放依赖探针。API 端口只允许内部网络访问。`FORWARDED_ALLOW_IPS` 只信任实际 Nginx 地址/网段，公网不得直接到达 API。不要未经评估增加 `/admin` 的公网代理。
8. 启动 API，检查 `/health` 为 200，并在 API 容器内部确认 `/ready` 为 200（Compose 健康检查自动执行）；验证登录、CSRF 刷新、公共浏览、上传和协同保存。邮件 worker/dispatcher 沿用原独立进程与持久任务表。

## 行为变化与运维边界

- `/ready` 探测 PostgreSQL 和 Session Redis；RabbitMQ 故障会暂停协同编辑，但不阻塞本地拼豆或已经登记的邮件任务，因此不作为整个 API 的就绪失败条件。
- Docker 健康状态不会自动重启仍存活的 unhealthy 容器，需要监控告警及现有运维处理。`restart: unless-stopped` 只处理进程退出。
- 默认通用限流为每主体、每端点 100 次/60 秒。压测需在隔离环境提高限额，429 与服务故障分开统计；不得全局关闭生产保护来解释吞吐。
- 公共图可见性改为数据库权威读取，会增加数据库读取量。后续如恢复缓存，必须先实现不会遗漏的权限撤回验证，不能仅依赖 TTL 或不可靠通知。
- COS 补偿属于尽力清理；删除失败记录对象键供人工核对。数据库与外部对象存储不具备跨系统事务，不能承诺物理对象绝对无残留。
- 单台服务器、单 PostgreSQL/Redis/RabbitMQ 仍有主机和存储单点。后续多节点需另行设计备份恢复、数据库复制、Redis/Sentinel、RabbitMQ 集群、负载均衡与告警；本轮不承诺生产容量或可用率。
- 增加 API worker 前确认共用同一数据库、Session/CSRF Redis、限流 Redis 与协同 RabbitMQ；不要启用内存 Session。容器扩缩容后应更新 Nginx 服务发现或重载配置。

## 验证

测试使用临时 PostgreSQL、Redis、RabbitMQ、Mailpit；COS/AI/搜索/OAuth 外部提供商仍模拟，不消耗真实额度。最终完整后端回归 **554 passed，0 failed，0 skipped**，Mypy 184 源文件与 Ruff 通过，前端生产构建及拼豆算法 11 项通过。官方 npm audit 为 0，OSV 查询 115 个公开包版本为 0 affected。命令与过程记录见当日开发交接；首轮失败及修复后的复测不得混为同一次全绿结果。
